Why it is vendored
------------------
The Windows kernel needs a target-matched static libvpx that a Cargo build can
link by name. vcpkg's built-in libvpx port builds a library whose Windows file
name carries a CRT/config suffix, so `cargo:rustc-link-lib=static=vpx` cannot
address it. Two of the vendored files remove that difference:

- 0004-remove-library-suffixes.patch: libvpx's MSVC project sets TargetName to
  `${name}${lib_sfx}${config_suffix}`; the patch sets it to `${name}`, which is
  what makes the installed static library a single `vpx.lib`.
- 0003-add-uwp-v142-and-v143-support.patch: the same overlay's UWP/toolset
  support, kept because it is part of the pinned port the upstream Windows
  build uses; this project installs the desktop triplet only.

portfile.cmake deliberately uses libvpx's own install target, so the install
layout is the one `build.rs` verifies: `include/vpx/vpx_decoder.h`,
`lib/vpx.lib` and `lib/pkgconfig/vpx.pc`.

How it is consumed
------------------
`.github/workflows/windows.yml` checks out microsoft/vcpkg at the commit
native/frb/UPSTREAM.txt and native/frb/UPSTREAM.lock both pin
(9e593bb18ea69cc5095e012465dcd675a822ed0d), installs
`libvpx:x64-windows-static-md` with `--overlay-ports` pointing at this parent
directory, asserts those three installed files exist, and exports
`LIBVPX_PREFIX` to the features that link it. `scripts/sync-client-to-windows.sh`
takes `REMOTE_LIBVPX_PREFIX` for the same purpose on a Windows host the operator
provisions.

What this directory is not
--------------------------
It is provisioning, not a decoder: no VP8/VP9 code lives here and none is
vendored from libvpx. The decoder is the engine's own
(`src/platform/vpx_decoder.rs`) and it links whatever install
`LIBVPX_PREFIX`/pkg-config names, verified by its own build script.

Not verified here: no vcpkg install, Cargo build, link or test was run while
adding this directory. The Windows workflow is where the port is installed,
where `include/vpx/vpx_decoder.h`, `lib/vpx.lib` and `lib/pkgconfig/vpx.pc` are
checked, and where the linked VP8/VP9 probe test is executed; until a Windows
runner reports that pass, the static library name, the triplet layout and the
probe evidence are static statements, not observed ones.
